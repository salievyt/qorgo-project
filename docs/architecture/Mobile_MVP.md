# QORGO: рабочий MVP

## Реализованные сценарии

- Регистрация и вход по email и паролю. Пароль хранится на сервере в виде Django-хеша, токен — в Keychain/защищённом хранилище телефона.
- Профиль: чтение и изменение имени.
- До 20 доверенных контактов: создание, редактирование, удаление, международные номера, необязательный email, звонок и открытие SMS SOS.
- SOS: полный жест ползунка, запрос текущей геопозиции, запись тревоги и снимка получателей на сервере, очередь отправки, история и завершение тревоги.
- Сопровождение: место и срок прибытия, подтверждение/отмена. Серверный обработчик создаёт SOS при истечении срока без участия открытого приложения.
- Получение координат по запросу пользователя и открытие их во внешней карте. Отказ в геолокации не блокирует SOS.

SMS из приложения требует подтверждения отправки в системном приложении сообщений. Автоматическая отправка осуществляется сервером через Twilio SMS или SMTP email после подключения настоящего провайдера. При отсутствии провайдера отображается реальное состояние `unconfigured`; приложение не утверждает, что близкие получили сообщение. Push, OTP по телефону, семейное живое отслеживание, геозоны и запись доказательств в эту итерацию не входят.

## Направление зависимостей Flutter

`presentation → domain ← data`

- `domain/`: сущности без зависимости от Flutter и HTTP, контракты репозиториев и устройства, сценарии SaveContact / StartJourney / ActivateSos.
- `data/`: HTTP-клиент, преобразование API-данных в сущности, удалённый репозиторий, Keychain и платформенные адаптеры геолокации/звонка/SMS.
- `presentation/`: состояние экрана, формы, навигация, ошибки и загрузка. Виджеты не выполняют HTTP-запросы.
- `main.dart`: корень композиции; создаёт реализации и передаёт зависимости через конструкторы.

## Сохранность и отправка

Сервер хранит контакты, тревоги и сопровождения в SQLite для локальной разработки. Данные изолированы по владельцу; проверка владельца обязательна для чтения и изменения. При повторе SOS используется UUID запроса, сохранённый на устройстве до ответа сервера. Уникальный индекс предотвращает повторное создание тревоги. Получатели копируются в тревогу, поэтому последующее изменение контакта не меняет историю.

`pending → sending → accepted / unconfigured / unknown`

`accepted` означает принятие сервисом SMS/SMTP, а не доставку человеку. Подтверждённая доставка и webhook провайдера ещё не реализованы. Неопределённый результат не повторяется автоматически, чтобы не отправлять скрытые дубликаты. Явный повтор сопровождается предупреждением в приложении. Завершение тревоги отменяет ещё не отправленные сообщения; уже переданные провайдеру сообщения отозвать невозможно.

Таймер сравнивается с UTC-временем сервера. Позднее нажатие «Я добрался» сохраняет факт просрочки. Состояние не зависит от локального отсчёта и перезапуска телефона. Последний контакт нельзя удалить во время активного сопровождения.

## Развёртывание

Домен пользователя: `qorgo.service` в Cloudflare. Домен не является сервером; размещение и DNS не изменялись.

Локальный API: `http://127.0.0.1:8000/api` для iOS-симулятора. Адрес задаётся через `--dart-define=QORGO_API_URL=…`. Release-приложение требует HTTPS.

Перед публичным запуском необходимы: постоянно работающий сервер API и worker, HTTPS, приватный секрет Django, SMTP/Twilio, резервное копирование базы, мониторинг worker и подтверждение доставки провайдером. Для нескольких экземпляров сервера потребуется PostgreSQL и очередь задач. Текущий worker предназначен для одного экземпляра; сетевые уведомления выполняются вне транзакции БД.

## Проверки

- Серверные тесты: аутентификация, изоляция владельцев, CRUD контактов, идемпотентность SOS, таймеры и статусы отправки без реальных рассылок.
- Flutter-тесты: формы, навигация на узком телефоне, жест SOS, сохранение UUID после ошибки и перезапуска, истёкшая сессия.
- Реальная сборка и запуск на iOS-симуляторе проверяются отдельно от тестов с подменёнными платформенными сервисами.

### Результаты проверки 11 октября 2026

12 серверных тестов и 6 Flutter-тестов проходят. Интеграционный тест на реальном iOS-симуляторе iPhone 18 Pro / iOS 27 успешно проверил создание аккаунта, форму контакта, подтверждение таймера, запись SOS и восстановление сессии через настоящий Keychain и локальный HTTP API. Реальная отправка SMS/email не проверена: провайдеры не подключены.

Обычная версия приложения после интеграционного теста вновь запущена на iOS-симуляторе; экран регистрации подтверждён. Android debug APK собран успешно. Android-эмулятор не запускался.
